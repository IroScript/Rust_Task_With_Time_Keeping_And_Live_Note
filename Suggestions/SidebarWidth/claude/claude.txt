### The Bug

`panel_content_width` was computed **before** the `ScrollArea` opened:

```rust
// OLD — computed OUTSIDE ScrollArea, doesn't know scrollbar width yet
let panel_content_width = (CONTROL_PANEL_WIDTH - 40.0).max(0.0); // = 260px hardcoded
egui::ScrollArea::vertical().show(ui, |ui| {
    ui.set_width(panel_content_width); // ← already wrong when scrollbar appears
```

When egui's scrollbar appears (~12px wide), the interior loses those 12px — but `panel_content_width` still said 260px. Every widget sized against it overflowed 12px past the right edge, causing the cut-off you saw.

---

### The 6 Fixes Applied

| Location | Old | New |
|---|---|---|
| `panel_content_width` declaration | Static `CONTROL_PANEL_WIDTH - 40.0` outside ScrollArea | `ui.available_width()` **inside** ScrollArea |
| `ui.set_width/set_max_width` | Called after drag-detect block | Moved to top of ScrollArea, before everything |
| `text_width` (main input, ×2) | `panel_content_width - 80.0` | `ui.available_width() - 80.0` |
| `list_box_internal_width` | `panel_content_width - 48.0` | `ui.available_width() - 28.0` (tighter fit) |

Now `panel_content_width` reflects **actual post-scrollbar space** on every frame. All buttons (`+ Add Text`, `Set Interval`, `⏸ Pause Rotation`, `Clear All`) already used `ui.available_width() - 8.0` so they self-correct automatically once the container width is right.
